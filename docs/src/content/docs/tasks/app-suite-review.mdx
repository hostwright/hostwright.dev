---
title: Review a local app suite
description: Plan a multi-service Manifest v3 project and confirm only supported local behavior.
---

Hostwright describes a local application as one project with multiple services.
Use Manifest v3, provide CPU and memory requests and limits for every service,
and declare dependencies and probes only when they are supported by the
selected runtime.

## Review the project

1. Validate the manifest with `hostwright validate <manifest>`.
2. Inspect the full non-mutating plan with `hostwright plan <manifest>
   --output json`.
3. Check images, resource bounds, ports, volumes, commands, health behavior,
   and provider constraints.
4. Reject or remove unsupported Compose/orchestrator fields. Do not assume
   Hostwright will translate unsupported behavior.
5. If you choose to run the project, use the corresponding dry-run lifecycle
   command and review the plan before confirming it.

The importer supports only a documented Compose subset. Conversion produces
Manifest v3 text for review; it is not full Compose execution or Docker API
compatibility. See [Import a stack file](/tasks/stack-import/),
[Limitations](/reference/limitations/), and the
[core app-suite example](https://github.com/hostwright/hostwright/tree/main/examples/app-suite).
