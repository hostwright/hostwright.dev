Use the [Quick start](/getting-started/quick-start/) to validate and plan a
single-service Manifest v3 workload. It shows the supported Apple-silicon
image, explicit CPU and memory requests and limits, provider selection, dry-run,
and plan-hash confirmation flow.

## Before confirmation

Check the complete plan for the selected manifest and provider. Review image
identity, resource requests, limits, ports, commands, and any policy
explanations. Runtime-backed actions require an installed provider and
authenticated daemon authority.

The confirmed CLI revalidates the current plan. If the manifest, runtime, or
authority changes, produce and review a new dry-run before confirming again.
See the [CLI reference](/reference/cli/) for current lifecycle commands and
the [core Manifest reference](https://github.com/hostwright/hostwright/blob/main/docs/reference/manifest.md)
for exact field rules.
