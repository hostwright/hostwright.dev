---
title: Daemon
description: Hostwright's current-user daemon observes and reconciles supported local workloads through the same fenced lifecycle path as the CLI.
---

Hostwright provides a foreground daemon and an explicitly managed
current-user LaunchAgent. Both use the selected manifest, local SQLite
authority, and the Runtime Provider API. Background reconciliation remains
bounded by admission, maintenance, restart, health, ownership, and recovery
gates.

## Inspect the service

```bash
hostwright daemon status --output json
hostwright daemon validate --output json
```

Install, start, stop, upgrade, rollback, repair, and uninstall the daemon only
through the corresponding `hostwright daemon` commands. These are local service
changes; review their current plan and output carefully. Use `hostwright help`
for exact options on the installed build.

## Foreground mode

For development and troubleshooting, `hostwrightd --foreground` runs without
installing or changing the LaunchAgent. It observes the configured runtime,
records bounded local status and recovery evidence, and follows the shared
fenced lifecycle policy for supported changes.

## Qualification boundary

An installed daemon is an active development capability, not a GA support
claim. Sleep/wake, interruption recovery, pressure deferral, restart behavior,
cleanup, and live host qualification remain in the v0.0.2 gate. See the
[core daemon architecture](https://github.com/hostwright/hostwright/blob/main/docs/architecture/daemon.md)
and [Limitations](/reference/limitations/).
