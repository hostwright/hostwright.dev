title: Events and diagnostics
description: Inspect local events, recovery state, and privacy-safe support evidence.
---

Hostwright stores local operation and recovery evidence in SQLite schema v24.
State-backed commands use the documented Application Support database by
default; `--state-db` or `HOSTWRIGHT_STATE_DB` can select another path. See the
[state and paths reference](https://github.com/hostwright/hostwright/blob/main/docs/reference/local-paths.md).

## Events and traces

```bash
hostwright events --output json
hostwright traces status --output json
```

The event ledger is the durable local record; OSLog mirrors selected records
for troubleshooting. Event and trace views are bounded and redacted. They do
not upload data.

## Inspect and recover operations

```bash
hostwright recovery --output json
hostwright state integrity --output json
hostwright state backups --output json
```

Recovery inspection reports durable checkpoints and any required action. It
does not authorize broad cleanup or bypass ownership. Preserve reported
state and follow the exact recovery command before retrying a lifecycle
operation.

## Support bundles

```bash
hostwright diagnostics support preview --output json
hostwright diagnostics support create \
  --output-path /absolute/private/support.json \
  --confirm-preview <preview-hash> --output json
```

Support creation requires an explicit preview and confirmation. Bundles are
bounded and privacy-safe, but may still contain local context. Inspect the
bundle before sharing. Hostwright does not upload it automatically; see the
[core support-bundle guide](https://github.com/hostwright/hostwright/blob/main/docs/reference/support-bundles.md).
