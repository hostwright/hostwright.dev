Hostwright is a **Mac-native desired-state container platform** for [Apple container](/concepts/apple-container-boundary/) workloads.

You declare services in a versioned [`hostwright.yaml`](/reference/manifest/) manifest. Hostwright validates intent, computes a deterministic plan, persists exact desired/observed/operation identity, and crosses a typed runtime-provider boundary for every runtime action.

<Aside type="caution" title="In active development">
Hostwright is in active development and not production ready. `brew install
hostwright` does not exist today. Use the [documented source or vendor-tap installation](/getting-started/install-from-source/) and read
[Limitations](/reference/limitations/) before relying on behavior.
</Aside>

## Current development boundary

- Manifest v3, Runtime Provider API v2, Control API 2.2, and SQLite schema v24.
- Authenticated local daemon lifecycle with plan confirmation, durable reservations,
  recovery, ownership fencing, and exact cleanup.
- Narrow Compose import with explicit CPU/memory mapping, followed by separately
  confirmed local execution.
- Native desktop up/down/restart with confirmation, cancellation, and disconnect handling.
- Signed development archives and packages plus the vendor tap; current-source
  release qualification remains pending.

Multi-Mac, Kubernetes, Docker API/client parity, accelerators, scheduler optimization,
team/MDM/cloud features, automatic updates, and Homebrew-core publication are deferred.
Read [limitations](/reference/limitations/) and the exact [compatibility matrix](/reference/compatibility/).
