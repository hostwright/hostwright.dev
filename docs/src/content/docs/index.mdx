Hostwright manages local Apple container workloads through a command-line
interface and a native macOS app. It validates strict Manifest v3 YAML,
plans lifecycle changes, and records state in SQLite schema v24. Confirmed
runtime actions use the authenticated Control API 2.2 daemon and a declared
runtime provider.

<Aside type="caution" title="Development release">
Hostwright `0.0.2-dev` is not GA-qualified or production-ready. The vendor tap
offers an unsupported qualification build; `brew install hostwright` is not
available. Read [Compatibility](/reference/compatibility/) and
[Limitations](/reference/limitations/) before use.
</Aside>

## Current implementation

- Manifest v3 requires explicit CPU and memory requests and limits. Legacy
  manifests can be reviewed through a deterministic migration preview.
- Scheduler admission and local lifecycle actions use durable reservations,
  exact plan confirmation, and fail-closed authority checks.
- The narrow Compose importer converts supported input for review. Unsupported
  fields are rejected; Docker API and full Compose compatibility are outside
  the release scope.
- The native app supports authenticated local up, down, and restart with
  confirmation. Signed-app, VoiceOver, and package qualification remains
  pending.
- The local daemon, state recovery, support bundles, and installed distribution
  lifecycle have development implementations. Release qualification is still
  in progress.

Implementation does not mean release qualification. Current-source physical
runtime, desktop, VM, security, and signed-artifact evidence is still required
before `v0.0.2` can be called GA.
